# Mimo — live audio companion

Chrome extension: record the current tab and microphone, save three WebM files locally, and transcribe speech through our DeepInfra Qwen3-ASR 0.6B service. Audio windows leave the device for recognition; there is no local Whisper fallback or customer model download. AI notes can use HPOP or service-managed DeepInfra DeepSeek V4.1 Flash, selected between meetings. This build uses a loopback development relay; public deployment and per-user metering are deferred.

## Build and load

Requires Node.js 22+ and pnpm 11+ (tested with pnpm 11.25.0).

```sh
pnpm install --frozen-lockfile
pnpm check
```

1. Open `chrome://extensions`, enable **Developer mode**, and **Load unpacked** → this project's `dist` folder. If already installed, click **Reload** after rebuilding.
2. Open Mimo's **Settings**. Click **Allow microphone** and approve Chrome's prompt. The permission test immediately stops.
3. Start the developer-managed relay (`pnpm relay`) after configuring it as described in [cloud transcription setup](docs/CLOUD-TRANSCRIPTION.md). In **AI connection**, select HPOP (with your saved key) or managed DeepInfra, then select **Save connection**. AI is required to start a session. Transcription prepares automatically; no DeepInfra account/key is requested from extension users.
4. Return to YouTube, a browser meeting, or another ordinary website tab. Open Mimo's toolbar popup and press **Start listening**. The assistant side panel opens automatically. You can also press **Start listening** in an already-open inactive assistant panel; it rechecks the current website tab and uses the same setup checks.
5. The popup introduces **Mimo**, an interactive mint slime, and a separate **Start listening** action. **Join Mimo** opens the live surface. **Current understanding** is home; an additional contribution replaces it in the reading space. **Useful** saves feedback, then returns to the latest understanding with appreciation. **Skip**, clicking Mimo, and Escape return locally; **More → Dismiss** archives. New thoughts wait while one is being read. Clicking Mimo can revisit an available thought. Sources return to the originating view. Understanding and the active contribution share one violet reading surface, with Mimo on the upper edge and unboxed real recording time plus an independent icon-only Stop directly below it. Live memo, Transcript, and Settings form one labeled footer row. **Settings → Session history** opens saved thoughts and deeper analysis. Mimo and its recording controls appear only on Live memo; use that tab to reach Stop. Settings retains its own portrait, and its tab always remains Settings. Normal Transcript has no Current understanding return action; source-opened Transcript retains contextual Back. The eight-pose character responds to actual events and direct gestures, with reduced-motion and artwork-failure support.
6. Press **Stop & Save**. Chrome downloads timestamped `-combined.webm`, `-microphone.webm`, and `-tab.webm` files. The last speech may take a few more seconds to finish transcribing. The latest transcript remains available after audio downloads complete.

Each Listen action checks microphone access and hardware, packaged speech-detector preparation, and enabled AI with the selected provider configured. Incomplete setup blocks the session and opens Settings with a warning. AI checks do not make a paid API request or prove remote credentials/connectivity. After a successful start, a later recognition or API failure still preserves audio recording. Cloud recognition is a draft: check important wording, names, and numbers against the audio.

Do not reload the extension during a recording: committed audio can be offered for recovery, but the uncommitted tail may be lost.

## Scope and timing

- Captures one Chrome tab's output and the default microphone, independently of the meeting website's mute control. It does not capture other tabs or native Zoom/Feishu apps.
- Saves a mono combined recording and independently encoded microphone/tab recordings preserving their channel layout. Each requests 96 kbps WebM/Opus, about 130 MB/hour total before overhead.
- Transcribes only the combined stream. There are no speaker labels, page captions, word timestamps or translation. Required AI provides current understanding and selective additional contributions in Chrome’s docked side panel.
- Text appears after approximately 600 ms of silence, or an eight-second maximum speech window, plus inference time. This is passage-level near-real-time recognition, not continuously revised word-by-word captions.
- A silent source is valid. Very quiet speech may be rejected by the speech detector. Overlapping voices, speaker echo, background music, and natural Indonesian/English code switching can reduce accuracy. Headphones help; echo cancellation is requested for the microphone, not guaranteed.
- Chrome 116+ supports the recorder's API architecture. Transcription needs the local development relay and internet access; validation used Chrome 155 on an Apple M5 Mac with 16 GB RAM. Older browsers, other GPUs, Windows, and natural bilingual meetings are not verified.

## Storage, failure, and recovery

Audio commits to IndexedDB roughly once per second with a 16 MiB pending-write bound. No full-recording JavaScript byte array grows during capture. Export assembles stored Blob references and may use additional browser memory; constant export memory is not guaranteed.

Temporary audio is deleted after all three downloads succeed, or when you cancel saving. Canceling skips the remaining outputs for that recording; files already saved remain on disk and the transcript is preserved. **Retry Save** skips completed outputs; **Discard** removes retained audio. Existing version 0.1 combined recordings remain recoverable. Browser termination can interrupt capture; only committed chunks are recoverable and interrupted WebM files may be incomplete.

The latest transcript is stored separately from temporary audio. Reopening Chrome retains completed text and marks an interrupted transcript incomplete. Starting a new recording replaces the latest transcript, including when transcription is unavailable. The transcript is available through **Transcript** in the sidebar. PCM awaiting recognition is retained in the durable IndexedDB outbox and replayed after recovery.

There is one recognition call at a time. Failed windows remain queued and retry automatically with 2–30 second backoff; requests have a 50-second client deadline and a 45-second relay deadline. Stop flushes final speech and preserves queued recovery work. A new recording waits for pending transcription. Already-queued contiguous windows merge up to 16 seconds per request, without waiting to fill a batch. Recognition remains serial. Set LISTEN_ASR_BATCH_SECONDS=8 when building to restore individual-window dispatch; see the measured rollout report.

The hidden offscreen document remains alive while a download owns a Blob URL or transcription / final AI work is finishing. Cloud requests and packaged VAD resources are released after the pending queue drains. Browser download settings may still display save prompts.

## Implementation and reuse

- **Popup:** 320px shared-theme control with an interactive Mimo greeting, separate Start listening action, recording source title, Join Mimo action, labeled Stop/save and Settings footer, and actionable recovery. Start opens the assistant side panel in the original click gesture. The shared mascot supplies eight poses, bounded gestures, canonical fallback, and reduced-motion behavior. No framework or content script.
- **Service worker:** tab access, offscreen lifetime, authoritative state queries, model preparation before requesting short-lived tab capture tokens, serialized recording controls, downloads.
- **Offscreen document:** streams, Web Audio graph, three native MediaRecorders, IndexedDB writes; a separate branch of the mixed stream feeds transcription without changing speaker routing or stopping shared tracks.
- **Speech detection:** vad-web 0.0.30's Silero V5 wrapper and packaged resampling AudioWorklet; 16 kHz mono, 400 ms pre-roll, 600 ms silence, 250 ms minimum speech, eight-second windows with one-second overlap when forcibly split. The low-level wrapper avoids the SDK's whole-utterance buffer during long speech.
- **Cloud recognition:** exact float32 WAV windows go to the local relay, then DeepInfra Qwen3-ASR 0.6B. A durable IndexedDB outbox retries failed requests in order with 2–30 second backoff; successful delivery and outbox deletion commit atomically. Pending speech survives Stop and document restart. Local Whisper/Transformers.js are removed.
- **Messaging:** audio windows are sent from the offscreen document to the authenticated loopback relay. Chrome extension messages contain text, state, identifiers, and metadata. Each segment retains its session/segment ID and approximate recording-relative window start/end in milliseconds; these are not word alignment timestamps.

Permissions are `activeTab`, `tabCapture`, `offscreen`, `downloads`, `storage`, and `sidePanel`. Hosts are `https://hpop.ai/*` and the loopback development relay `http://127.0.0.1:8787/*`. The DeepInfra provider key stays in the backend-only ignored `.local/deepinfra.json`; the extension contains only a development relay access token. The relay binds to loopback and must not be exposed as a public unauthenticated service. No model/CDN permissions remain. Packaged VAD still needs its matching WASM/ONNX assets. See [attribution and licenses](THIRD_PARTY_NOTICES.md).
