# Layer 3: live meeting assistant

AI is **required for every new session**. Its configuration flag starts disabled until setup is complete; that initial state is not an optional product mode. Starting Listen requires microphone permission/hardware, prepared local ASR, and enabled AI with a saved key and HPOP permission. These checks do not make a paid request or verify remote key validity. A later runtime AI failure preserves already-running audio and local recognition.

In **Settings → AI connection**, enter your HPOP key, accept the transcript-transfer disclosure, and save. The key is kept in `chrome.storage.local` restricted to trusted extension contexts and the dedicated network worker's memory. It survives browser restart and extension reload/update/disable, is not synced, and is removed on explicit Remove key or uninstall. An available legacy session key migrates once into local storage. It is never included in the build, analysis database, logs, or settings responses. Removing the key also disables AI. Other preferences persist in local storage.

Automatic meeting analysis uses `claude-sonnet-5-5` internally. Settings does not expose a model selector or model name. Settings reads, connection saves, and session initialization normalize older saved model choices to this default. Benchmark certification remains separate from the configured product default. Benchmarks and the remaining gates are recorded in `ASSISTANT-VALIDATION.md`. Passing schema validation does not establish factual accuracy or usefulness.

## Use

Settings opens inside the same docked panel, from either the recorder popup or the assistant footer icon. The Settings footer icon becomes **Back to Assistant** and returns to the current assistant view: inactive Listen or the running meeting. Recording **Stop & Save** remains available while Settings is open. Preferences use the existing settings form and storage; a standalone setup page remains available through Chrome’s extension options and first-run onboarding.

1. Prepare local transcription and microphone access as before.
2. Configure AI in **AI connection**. Set an optional persistent objective separately in **Meeting defaults**; it applies to future sessions. HPOP and its upstream provider receive finalized transcript text, recent context, evidence-backed memory, and recent question feedback. No audio is sent.
3. Return to the source website and press **Listen**; the assistant opens automatically. An already-open inactive panel also offers a circular **Listen** button; it re-queries the current website tab on click and uses the same worker START action and microphone/model/AI requirements. During recording, **Open notes** reopens it if needed. This opens Chrome’s docked side panel in the same browser window. It stays visible while you click or type in the page, and can remain open across tabs. Recording stays bound to the original source tab. Chrome controls which side the panel appears on.
4. The assistant shows one living meeting memo: a topical title, brief overview, and only supported section headings/bullets. The compact activity line describes actual recording, transcription, analysis, retry and failure; its bounded signal stops under reduced motion. There is no brand bar, revision feed, latest-speech preview or per-entry metadata. Footer icons provide **Transcript**, **More insights**, **Settings**, and **Stop & save**, each named accessibly and with a tooltip. Transcript remains available during saving. Complete validated memo updates retain unchanged DOM blocks and anchor reading position; **Notes updated** appears when updates arrive while away, without auto-jumping. Transcript and optional question evidence open details with Back navigation. Sources show supplied input context, not verified claim-level citations. Insights invoked from Settings closes Settings and opens the visible detail.
5. A completed, locally validated follow-up appears when the model identifies an important gap. Silence is valid: it can return no question. **Useful** records feedback; **Dismiss** removes the suggestion. These buttons suppress repetition within the recent history; they do not send a question to meeting participants or retrain a model.
6. **Analyze deeper** asks `claude-opus-5-5` for a separate analysis. It has a separate request slot and a 30-second deadline. Automatic suggestions continue. Closing the assistant panel leaves recording, recognition, and AI running.
7. **Stop & Save** stops capture normally and saves the three audio files. Local transcription finishes first; the assistant then has one final 30-second budget. Incomplete final AI work is canceled and labeled. Deeper work is canceled on stop.

**Settings → Appearance** offers **Automatic · local time** (default), **Midnight**, and **Daylight**. Automatic selects Midnight from local 18:00–06:00 and Daylight from 06:00–18:00. The panel re-evaluates the schedule every second and when visibility returns, including local clock/timezone changes. Selection saves immediately to `chrome.storage.local` under `listenAssistantAppearance`, which intentionally supersedes `listenAssistantSurface` so existing installations adopt Automatic. There is no browser color-scheme System mode. The same saved Appearance applies to the popup, assistant, docked Settings, and standalone Settings. Settings preserves its existing list/detail flow, drafts, focus, and inline feedback.

The inactive view contains the circular Listen control, current website tab name, capture hint, and a Settings-only footer. It hides saved memo/transcript content. Connecting remains on the control until capture begins; preparation and other busy work disable start. Actual recording, saving, and final processing retain the live view; failed saving retains recovery controls. Start failures remain visible and recoverable and can route to Settings. Saved summary data remains stored internally while idle hides it; starting a new session clears old visible meeting content.

The current question can remain visible while later updates contain no new question. It is removed when dismissed or explicitly resolved by an evidence-backed memory update. Questions cite segment IDs; segment times remain approximate capture-window timestamps, not word alignment.

## Scheduling and bounded work

- Only finalized ASR passages trigger requests. Arrivals coalesce for 150 ms; automatic starts are at least two seconds apart. One automatic request runs at a time. New speech becomes one combined pending update, never a per-passage request queue.
- The request separates unprocessed new passages (`newTranscript`) from earlier transcript context and supplies the complete current memo (`previousSummary`). Up to eight legacy takeaways fit an estimated 700-token bound until consolidation. Transcript context covers roughly the latest 90 seconds, bounded to an estimated 2,500 tokens; evidence memory is bounded to an estimated 1,000 tokens. The estimator uses UTF-8 JSON bytes divided by three, not an exact provider tokenizer. Oversized passages are truncated and an explicit context-gap flag accompanies omitted discussion. Finite context and compact minutes cannot preserve every detail.
- Each result is checked against a strict local Zod schema and known segment IDs. Summary text and questions are hidden until the complete response validates; transport streaming does not stream words into the interface. Session generations and monotonically increasing accepted versions reject stale results. Issue keys and normalized text overlap suppress repeated questions. Semantic correctness and whether something was already answered still depend on model behavior and quality evaluation.
- Memory distinguishes facts, decisions, open issues and resolved issues with source IDs. The latest session snapshot is stored in the separate `listen-assistant` database; audio cleanup does not delete it. The model returns a complete revised memo, preserving supported earlier commitments and replacing corrected facts, aiming for 120–200 words with a 2,400-character schema maximum. A changed validated memo replaces `summaries` with one `format: 'memo'` object containing current bounded memory and the union of prior, new-passage and memory-update evidence IDs. Empty or normalized unchanged responses retain the memo and advance processing. Old incremental notes are deduplicated and joined into one fallback until the next substantive model response consolidates them. New recordings replace prior analysis; idle hides stored analysis. Memo text is parsed into title, section, paragraph and list DOM blocks without executing HTML or links. This is concise minutes, not exhaustive full-meeting retention; consult transcript/audio for detail.

## API boundary and failure behavior

Only `https://hpop.ai` is permitted for AI traffic. Redirects fail rather than sending an authenticated request elsewhere. The manifest grants this one host; sending transcript text additionally requires explicit AI authorization during configuration, which is required to start a new session. Hugging Face hosts remain permitted only for the existing model download. The `sidePanel` permission hosts the assistant alongside the webpage. There is no content script, page overlay, analytics, or automatic participation.

GPT and Qwen use OpenAI streaming Chat Completions with JSON Schema. HPOP's Claude Chat Completions route did not enforce the requested schema in the initial probe; Claude candidates therefore use the native `/v1/messages` compatibility adapter, with a forced schema-bearing tool result. Both transports use the official OpenAI JavaScript SDK, including its generic SSE transport for native events. Local validation remains mandatory. Model configuration acceptance is not proof of upstream forwarding; no unsupported or unverified route is certified silently.

Automatic responses have a 1,600-token output budget. Automatic requests share a 30-second deadline across the SDK, network worker and completion validation; the client watchdog allows an additional 250 ms for the worker reply. There are zero SDK retries. The controller permits at most three consecutive attempts, with backoff and `Retry-After` handling, then pauses. Authentication/authorization errors pause immediately. Resume AI retries after settings are corrected. SDK timeout/abort errors are classified before their APIError superclass, so timeouts are distinct from network failures and HTTP 5xx service failures. Errors are reduced to safe status/category messages and never include response bodies or credentials. Audio and recognition continue independently. Pending context is retained within the bounds above; prolonged failures report gaps.

The service worker coordinates Chrome APIs and stores settings/key metadata. The offscreen document owns the scheduler and a dedicated network worker. No popup polling, artificial keepalive loop, or side-panel lifetime is required for AI. The offscreen document closes only after capture, all audio downloads, transcription, and final AI work have settled. Final analysis persistence has an additional bounded two-second flush window; a stalled write is reported instead of keeping the document alive indefinitely.

## Manual acceptance checklist

- Start a consenting work meeting; confirm both source meters and local transcription before evaluating AI.
- Discuss a consequential missing owner, deadline, dependency, or cost; confirm the suggestion is supported, timely, and in the conversation's language. Also discuss already-resolved facts and small talk; expect silence.
- Mark a question Useful or Dismiss; restate the issue in different wording and check that it is not repeatedly shown. Answer the question and check that later memory resolves it.
- Close/reopen Assistant, switch tabs, and let the service worker suspend; recording and analysis should continue against the original session. Start a new recording and confirm no previous meeting's analysis leaks in.
- Remove the saved key or interrupt the API; local recording/transcription should continue. Correct Settings and Resume AI. Restart Chrome or reload the same unpacked extension and verify that the key is retained while saved analysis is not shown as a live connection.
- Use Analyze deeper during automatic updates; stop while it is running. Confirm canceled work cannot overwrite a later session, the final update is bounded, all three audio exports play, and the offscreen document is eventually released.

Natural-meeting usefulness, headed desktop permission UX, and upstream reasoning-control verification remain open acceptance items; synthetic tests do not check them.
